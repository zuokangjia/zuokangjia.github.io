Mininet的原理和应用
2026-11-04 22:36:31 #Mininet #Linux Container #SDN

Mininet可以创建一个含有主机、交换机、控制器和链路的虚拟网络，其交换机支持OpenFlow，具有高度灵活的自定义软件定义网络；同时，在 Mininet 上写的代码（比如控制器和 OpenFlow 应用）也可以迁移到真实的网络环境中运行。

Mininet的由来

Mininet是由斯坦福大学基于Linux Container架构开发的一个轻量级网络仿真工具（更准确的说法是 emulator：跑的是真实的内核网络栈、交换机代码和用户态程序）。它采用轻量级的虚拟化技术，使一台机器看起来像一个完整的网络，每个节点都有自己的网络栈和用户态进程；也可简单理解为 SDN 网络系统中的一种容器级仿真平台，其交换机支持 OpenFlow，默认使用 Open vSwitch（OVS）。

其最早的论文《A Network in a Laptop: Rapid Prototyping for Software-Defined Networks》发表在 2010 年的 HotNets（HotNets-IX）会议上，作者是斯坦福大学的 Bob Lantz、Brandon Heller、Nick McKeown，其中 McKeown 也是 OpenFlow 协议的主要设计者。

Mininet的原理和架构

Linux Container

Linux 的命名空间是逐步加进来的：mount（2.4.19）、uts/ipc（2.6.19）、pid/net（2.6.24），后来的 user（3.8）、cgroup（4.6）、time（5.6）。Mininet 主要用到的是网络命名空间（以及 mount），下面三个是经常被拿出来对比的。

  • 网络命名空间：一套独立的网络栈，包括网卡、路由表、防火墙规则、端口等；每个进程都归属于某个网络命名空间。
  • 进程命名空间：一套独立的进程树，不同 namespace 里可以有相同的 PID，进程只能看到同一 namespace 里的其他进程。
  • 用户命名空间：隔离的是用户 ID、组 ID 的映射和 capability 边界，不是文件系统、网络接口或进程列表；而且它是 3.8 才加入的（Mininet 需要 root，并不依赖它）。

每种命名空间只管一类资源：mount 管挂载表，pid 管进程树，net 管网络栈，不能混在一起说。

每个命名空间里的资源对其他命名空间是隔离、不可见的，所以不同 PID namespace 里可以出现相同 PID 的进程。还要注意，宿主机上的 ps 能看到所有进程；Mininet 的主机没有单独的 PID 命名空间，所以在 h1 里执行 ps 看到的也是整机进程。这样一来，每个命名空间看上去就像一个单独的 Linux 系统。

在Mininet开源项目提供的教学案例中，有提到具体的Linux Container的实现原理。

最简单的网络实现

使用两个namespace，分别为h1和h2，用于模拟host1和host2。

通过虚拟化实现对主机和网络通信的模拟

两个namespace之间通过veth pair（virtual ethernet pair）连接，veth pair是一种虚拟设备，它可以用来在两个命名空间之间传输数据。更加复杂的网络环境，可以使用Linux bridge、Open vSwitch等虚拟交换机。

Mininet正是使用这种Linux Container技术实现的虚拟网络环境。使用python语言编写的Mininet代码，通过调用Linux系统的命名空间和网络管理工具，可以创建多个虚拟网络环境，并在这些环境中模拟真实网络环境的各种功能。

Mininet的架构

在一个laptop中的模拟器mininet

Mininet的架构是按照SDN的架构来设计的，分为虚拟化层和控制层。

虚拟化层：创建虚拟的网络设备，包括主机、交换机、链路等，对应SDN中的数据平面。

控制层：Mininet自己的编排管理，负责启动、停止、配置、监控虚拟网络，对应的是 Mininet 的 Python API 和 CLI；它不是 SDN 里管流表的控制平面，那个是外部的控制器。

  1. Mininet的主要组件包括：网络对象（Net）、控制器、主机、交换机、链路。
  2. 控制器：通过 OpenFlow 给交换机下发流表，不直接管理主机和链路。Mininet 自带一个简单的学习交换机控制器，也可以接 Ryu、ODL 等外部控制器；--controller none 时也可以完全不用控制器。
  3. 主机：主机是运行在独立网络命名空间里的进程，不是物理机也不是虚拟机。
  4. 交换机：交换机是 Open vSwitch 等软件交换机，不是物理交换机。
  5. 链路：链路是 veth pair 这类虚拟链路，不是物理链路；TCLink 还可以给它加上带宽、延迟、丢包等参数。
  6. Mininet的架构可以分为两层，第一层是虚拟化层，它负责创建虚拟网络环境，包括创建主机、交换机、链路等；第二层是控制层，它负责管理虚拟网络环境，包括启动、停止、配置、监控虚拟网络等。

Mininet可以做什么

Mininet 是一个 emulator（仿真器），和 ns-3 这类 simulator（模拟器）最大的不同在于：它跑的是真实的内核网络栈、交换机代码和用户态程序，只是网络设备是虚拟出来的，所以能在虚拟环境里运行各种真实的网络服务。

Mininet可以做以下事情：

  • 为OpenFlow应用程序提供一个简单、便宜的网络测试平台
  • 启用复杂的拓扑测试，无需连接物理网络
  • 具有拓扑感知和OpenFlow感知的CLI，用于调试或运行网络范围的测试
  • 支持任意自定义拓扑，主机数可达4096，并包括一组基本的参数化拓扑
  • 提供用于网络创建和实验的可扩展Python API

Mininet的使用

Mininet提供了一系列的命令行工具，用于创建、配置、运行、监控虚拟网络。

mininet命令树

网络构建参数

  • --topo：指定拓扑类型，内置的有 minimal、linear、reversed、single、tree、torus 等。
  • --controller：指定要使用的控制器类型，内置的有 default、ref、ovsc、nox、remote、ryu、none；要接 ODL、ONOS 这类外部控制器，用 remote 加地址，比如 --controller remote,ip=127.0.0.1。
  • --switch：指定交换机类型，默认是 ovs（Open vSwitch），还支持 ovsk（2.0 兼容名）、ovsbr、ivs、lxbr、user 等。
  • --custom：指定自定义拓扑文件。
  • --mac：按顺序而非随机分配主机的MAC地址。设置简单唯一，肉眼也能看出mac地址对应的主机。

内部交互命令

使用sudo mn启动Mininet的命令行界面，可以输入内部命令，包括：

  • net：查看当前网络状态。
  • nodes：查看当前网络中的主机、交换机、控制器。
  • links：查看当前网络中的链路的状态。
  • intfs：查看当前网络中的接口的状态。
  • pingall：所有的主机之间互相ping，测试网络是否通畅。
  • xterm：对一个主机打开一个新的xterm窗口，用于运行主机上的命令。
  • dpctl：对OpenFlow交换机进行流表的操作（已废弃，现在一般用 ovs-ofctl）。
  • iperf：测试主机之间的TCP流量带宽。
  • iperfudp：测试主机之间的UDP流量带宽。

另外，ovs-ofctl、ovs-vsctl、mnexec 不是 CLI 内置命令，要在对应节点上执行：

  • s1 ovs-ofctl ...：对 OpenFlow 交换机进行操作，比如 s1 ovs-ofctl dump-flows。
  • s1 ovs-vsctl ...：配置 Open vSwitch 的 bridge、端口等，比如 s1 ovs-vsctl show。
  • mnexec：Mininet 用来在节点的命名空间里执行命令的底层小工具（mnexec -n 会 unshare 网络和 mount 命名空间）；CLI 里日常更常用的是直接写 h1 <命令>。
